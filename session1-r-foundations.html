Why write code at all?

The alternative is worse

You could do all of this by pointing and clicking in Excel or SPSS. Here is why we don’t:

  • You can check your own work. Six months from now, “how did I define preterm?” has an answer.
  • Your supervisor can check your work. So can a peer reviewer, and so can you when a reviewer asks.
  • The Methods section writes itself. Your script is the methods section.
  • Data changes. Constantly. New cases arrive, a variable gets corrected, you discover an exclusion you missed. Re-running a script takes 30 seconds. Redoing 40 clicks takes an afternoon and introduces new errors.
  • Reproducibility is now an expectation, from CIHR, from journals, and from ICES.

A script is a permanent, auditable record of every decision you made about the data. That record is the actual scientific product — the p-value is just the last line.

R’s building blocks

R is a calculator that remembers things

Anything after # is a comment. Comment generously — the person reading your code in six months is you, and you will have forgotten everything.

Assignment: making things stick

Use <- to give a value a name. (= also works, but <- is the convention and reads as “gets”.)

Naming: lowercase, words separated by _, no spaces, don’t start with a number. birth_weight_g is a good name. bw2FINAL is a crime against your future self.

Vectors: R’s atom

Almost everything in R is a vector — an ordered collection of values of the same type. c() combines things into one.

Vectorisation is the single biggest mental shift from SAS. In SAS you think one row at a time. In R you operate on whole columns at once.

The four types you will meet

That silent coercion is a classic bug source. One stray "N/A" typed into a birth-weight column turns the whole column into text, and mean() then fails.

Your turn: vectors

Five infants’ birth weights in grams. Fill in the blanks to get the mean in kilograms and the number of low-birth-weight (<2500 g) infants.

Hint

mean() takes the vector itself. To convert grams to kilograms, divide by 1000. For the count, you want the comparison operator “less than”.

Solution

bw <- c(3250, 2410, 4100, 1980, 3600) mean(bw) / 1000 sum(bw < 2500) 
bw <- c(3250, 2410, 4100, 1980, 3600)

mean(bw) / 1000

sum(bw < 2500)

Missing values are their own thing

NA is not zero, not "", and not “unknown text”. It is R’s explicit marker for missing.

mean(x) returning NA is a feature. It forces you to notice missingness and make a deliberate decision, instead of silently analysing a complete-case subset you never chose.

Factors: categorical variables with rules

A factor is a categorical variable with a fixed set of levels and — critically for us — a reference level.

This matters for your regressions. The first level is the reference group. By default R sorts alphabetically, so "exposed" beats "unexposed" and your odds ratio comes out upside down. Set levels explicitly. Always.

Rectangular data

Data frames

A data frame is what you actually analyse: columns of equal length, each with its own type. One row = one observation. This is a SAS dataset, a Stata .dta, an Excel sheet.

Looking at a data frame

Packages and the working environment

Packages

Base R is deliberately small. Everything else lives in packages — over 22,000 of them on CRAN.

# ONCE per computer
install.packages("tidyverse")

# EVERY session, in your script
library(tidyverse)

Install once, library every time. Never put install.packages() in a script you share — it re-downloads on someone else’s machine without asking.

Worth knowing about

  • tidyverse — dplyr, ggplot2, readr, … (second session)
  • haven — read SAS .sas7bdat files directly
  • janitor — clean messy variable names
  • gtsummary / tableone — publication “Table 1”
  • survival, lme4, mice, survey

pkg::function() calls a function without loading the whole package — e.g. haven::read_sas(). Useful, and it documents where a function came from.

RStudio: the four panes

1 · Source (top-left) Your script. This is the real work. Write here, not in the console. Ctrl/Cmd + Enter runs the current line.

2 · Environment (top-right) Every object you’ve created, with its size and type. Also the History tab.

3 · Console (bottom-left) Where code actually executes. Fine for throwaway checks — anything you’d want again belongs in the script.

4 · Files / Plots / Packages / Help (bottom-right) Your working directory, your figures, and the help pages.

The one habit that matters: work in the Source pane, not the Console. If it only ever happened in the Console, it didn’t happen.

Projects, and never using setwd()

Do this

# File > New Project > New Directory
# then open the .Rproj file

# paths are relative to the project root
births <- read_csv("data/births.csv")

The project root is your working directory. Move the folder, email it, put it on OneDrive — it still works.

Not this

setwd("C:/Users/shawken/Desktop/
       thesis/final/FINAL2/data")

This runs on exactly one computer, until you reorganise your Desktop. It is the single most common reason a supervisor cannot run a student’s code.

Tools > Global Options > General: set Save workspace to .RData on exit to Never, and untick Restore .RData at startup. You want your script to rebuild everything from scratch, every time. That is what reproducible means.

A working tour of SAS

Why you still need SAS 15 min

  • ICES, ICES-uOttawa, TOHDW, CIHI, BORN, StatCan RDCs all run on it. Large linked administrative holdings, decades of validated code, and analysts who know it cold.
  • It handles data larger than memory without you thinking about it — R will fall over on a 40-million-row OHIP claims extract where SAS shrugs.
  • Your supervisor’s existing analysis code is probably SAS. You will need to read it, and you will need to check it.
  • It is extremely stable. Code written in 2004 still runs. That is a real virtue for a cohort study that has been running since 2004.

Goal for the next 15 minutes: not fluency. Enough SAS literacy to read someone else’s program, run it, and know when the log is lying to you.

The whole language, in one idea

SAS has exactly two kinds of step, and everything is one or the other.

DATA step

Reads and writes datasets one row at a time. Creating variables, filtering, merging, recoding.

DATA preterm;
  SET births;
  IF ga_weeks < 37;
  bw_kg = birth_weight_g / 1000;
RUN;

PROC step

Does something to a whole table. Summarising, tabulating, modelling, plotting.

PROC MEANS DATA=births;
  CLASS site;
  VAR birth_weight_g;
RUN;

Every statement ends with a semicolon. A missing ; is responsible for roughly 90% of the time you will lose to SAS. Not an exaggeration.

Libraries: where datasets live

/* WORK is temporary — everything in it vanishes when SAS closes */
DATA births;          /* really WORK.births */
  SET mylib.births;
RUN;

/* LIBNAME points a nickname at a folder, for permanent storage */
LIBNAME mylib "/home/steven.hawken0/seminar/data";

DATA mylib.births_clean;   /* saved to disk as births_clean.sas7bdat */
  SET births;
RUN;

R equivalent 

births        # lives in memory only
saveRDS(births, "data/births.rds")

The mental model

WORK. = R’s environment. LIBNAME = a folder on disk. Two-level name = library.dataset.

Demo 1 — make a dataset and look at it

DATA clinic;
  INPUT id site $ ga_weeks bw_g;
  bw_kg = bw_g / 1000;
  preterm = (ga_weeks < 37);      /* a 0/1 flag: the condition IS the value */
  DATALINES;
1 Ottawa   38.4 3250
2 Ottawa   41.1 4100
3 Kingston 34.0 2280
4 Sudbury  39.7 3510
5 Kingston 27.3  980
;
RUN;

PROC PRINT DATA=clinic; RUN;
PROC CONTENTS DATA=clinic VARNUM; RUN;

$ after a variable name means “this one is character”. VARNUM lists variables in creation order instead of alphabetically — always use it.

Demo 2 — import, describe, tabulate

PROC IMPORT DATAFILE="/home/steven.hawken0/seminar/data/births.csv"
  OUT=births DBMS=CSV REPLACE;
  GETNAMES=YES;
RUN;

PROC FREQ DATA=births;
  TABLES sex site sex*site / NOPERCENT NOCOL;
RUN;

PROC MEANS DATA=births N MEAN STD MIN MAX;
  CLASS site;
  VAR ga_weeks birth_weight_g;
RUN;

  HISTOGRAM / NORMAL;
RUN;

Read the log. Every time.

SAS will happily produce beautiful, confident, wrong output and tell you about it only in the log.

Three words to search for

  • ERROR — it stopped. You’ll notice.
  • WARNING — it kept going. You might not notice.
  • NOTE — the dangerous one.

The NOTEs that ruin analyses

NOTE: Invalid numeric data, 'N/A'
NOTE: Missing values were generated
NOTE: MERGE statement has more than
      one dataset with repeats of BY

Check N after every step. If births had 1,239 observations and your merged dataset has 1,372, you have a problem — and SAS told you about it in a NOTE you scrolled past. We will do exactly this bug live in R in the second session.

Two SAS habits worth stealing

Comment out, don’t delete

DATA cohort;
  SET births;
  IF ga_weeks >= 22;
* IF ga_weeks >= 20;   /* prior defn */
RUN;
/* N = 1239 */

Record what each version gave you. Reviewers ask.

Recovering from unbalanced quotes

*'; *"; */;

If a stray quote makes SAS unresponsive, run that line (sometimes twice). Harmless if nothing is wrong; saves you a restart if something is. Tape it to your monitor.
