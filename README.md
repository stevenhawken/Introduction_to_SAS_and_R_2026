# Intro to R & SAS — MSc Epidemiology Grad Seminar

Two one-hour sessions. The slides are **Quarto `live-revealjs` decks**: every code box
is a real R session running in the student's browser via WebAssembly, so Session 1
needs nothing installed on their end.

## Rendering

You need **Quarto** (ships with RStudio ≥ 2022.07) and **R with `knitr` + `rmarkdown`**.
The `_extensions/` folder is already here, so:

```bash
quarto render session1-r-foundations.qmd
quarto render session2-r-workflow-ai.qmd
```

Or open the `.qmd` in RStudio and click **Render**.

To update the bundled extension later:

```bash
quarto update r-wasm/quarto-live
```

### Distributing the slides

The rendered `.html` needs two companions in the same folder:

```
session1-r-foundations.html
session1-r-foundations_files/     <- fonts, reveal.js, the webR runtime
data/                             <- the CSVs the live cells read
```

Put those three on Brightspace (or any static web host — GitHub Pages, Quarto Pub,
Netlify) and send students the link. **Opening the HTML from a local file path will
not work** — browsers block the workers webR needs. Students need the hosted URL.

## Before you present — 5-minute smoke test

The live cells run in a browser, which means they can't be verified by rendering alone.
Please do this once, on the projector machine, on the venue wifi:

1. Open the **hosted** slide URL (not the local file).
2. Wait for the first Run button to go from greyed-out to active — this is webR
   downloading (~15–25 s the first time; it caches afterwards).
3. Session 1: run the `2 + 2` cell, then the `read.csv("data/births.csv")` cell.
4. Session 2: check that the hidden setup cell worked by running the `glimpse(births)` cell.
5. Open one exercise, click **Show solution**, then **Start Over**.

If step 2 hangs, the venue network is blocking `cdn.jsdelivr.net` or
`repo.r-wasm.org` — that's where webR and its packages come from.
**Fallback:** the `session2-workbook.Rmd` covers the same material in RStudio,
and the decks still work as ordinary slides with the code visible.

## The data

All four files are **fully synthetic** — generated by `make-data.R`, safe to post
publicly and safe to paste into an AI assistant. The structure mirrors a linked
perinatal / newborn-screening analysis.

| File | Unit | n |
|---|---|---|
| `births.csv` | one row per infant | 1,239 |
| `mothers.csv` | one row per mother | 1,200 |
| `screening.csv` | one row per **specimen** | 1,338 |
| `patients.csv` | 12 adults, Session 1 toy example | 12 |

### Deliberate teaching landmines

Each one drives a specific slide. Don't "fix" them in the data.

| In the data | Teaches |
|---|---|
| 133 infants have a **repeat specimen** | `left_join()` inflates 1,239 → 1,372 rows, silently |
| 39 mothers have **twins** | many-to-one on `momid`; non-independent observations |
| 34 infants have **no screening record** | `anti_join()` as an audit; selection bias |
| `sex` coded `F`/`M`/`f`/`m` | data cleaning before stratification |
| `x17ohp` right-skewed, 80 missing | log transformation; `na.rm`; GA-stratified cut-points |
| `mat_bmi` 60 missing | complete-case analysis is an assumption, not a default |

Real associations built in (so the models on the slides find something):
GA ↑ → birth weight ↑ (≈199 g/week); male infants ≈ +174 g; smoking → lower birth
weight and OR ≈ 2.3 for preterm; pre-existing diabetes OR ≈ 2.1 for preterm;
hypertension raises preterm risk but is **underpowered** — a good discussion point.

`make-data.R` is seeded (`set.seed(20260917)`). Re-running it reproduces these files
exactly. **If you change it, update the row counts quoted on the Session 2 slides**
(search the `.qmd` for `1239`, `1200`, `1338`, `1372`, `133`).

## Running order on the day

**Session 1** — assume zero installs. Students open the slide link and follow along.
Homework at the end is to install R + RStudio.

**Session 2** — assume RStudio. Students can use either the live cells or
`session2-workbook.Rmd` in RStudio; the workbook is also the take-home.

The SAS segment is live in **SAS OnDemand for Academics** — upload `data/` and the
two `.sas` files to your OnDemand Files area first, and edit the `%LET root = ...`
line at the top of each script.
